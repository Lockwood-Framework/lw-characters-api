# lw-characters-api

Character identity, slot management, tombstone tracking, and account-level name uniqueness for Lockwood RP.

**Phase:** API  
**Dependencies:** `lw-db`, `lw-shared`, `lw-core`

---

## Overview

This resource is a pure data layer. It owns two database tables — `lw_characters` and `lw_character_tombstones` — and exposes everything above it via exports. It has no client scripts and no gameplay logic. Other resources call into it; it does not call into them.

---

## Configuration

`server/config.lua`

| Key | Default | Description |
|---|---|---|
| `Config.DefaultSlots` | `4` | Character slots per player |
| `Config.MaxSlots` | `8` | Hard ceiling — overrides above this are clamped at startup with a console warning |
| `Config.MaxEpitaphLength` | `250` | Maximum epitaph length in characters |
| `Config.SaveInterval` | `300` | Seconds between periodic location saves |
| `Config.SlotOverrides` | `{}` | Per-player slot overrides keyed by `license2` identifier |

Slot allowances are in-memory only. No database column. Changes take effect on server restart.

## Database

### `lw_characters`

| Column | Type | Notes |
|---|---|---|
| `state_id` | VARCHAR(17) PK | Generated by lw-core, inserted here |
| `license2` | VARCHAR(60) NOT NULL | FK → lw_players.license2, ON UPDATE CASCADE ON DELETE CASCADE |
| `first_name` | VARCHAR(32) NOT NULL | |
| `last_name` | VARCHAR(32) NOT NULL | |
| `status` | ENUM('active','deceased') | Default `active` |
| `last_x` | FLOAT NULL | NULL until first save |
| `last_y` | FLOAT NULL | NULL until first save |
| `last_z` | FLOAT NULL | NULL until first save |
| `last_heading` | FLOAT NULL | NULL until first save |
| `deceased_at` | TIMESTAMP NULL | Set by `SetCharacterDeceased` |
| `created_at` | TIMESTAMP | |
| `last_played_at` | TIMESTAMP | Updated on `lw-core:characterSelected` |

### `lw_character_tombstones`

| Column | Type | Notes |
|---|---|---|
| `state_id` | VARCHAR(17) PK | Persists after character row is deleted |
| `license2` | VARCHAR(60) NOT NULL | |
| `first_name` | VARCHAR(32) NOT NULL | |
| `last_name` | VARCHAR(32) NOT NULL | |
| `epitaph` | VARCHAR(250) NULL | NULL = no memorial entry |
| `died_at` | TIMESTAMP | |

### Extension tables

Any resource that extends a character must key its table to `state_id` with:

```sql
CONSTRAINT `fk_mytable_state_id`
    FOREIGN KEY (`state_id`)
    REFERENCES `lw_characters` (`state_id`)
    ON UPDATE CASCADE
    ON DELETE CASCADE
```

This ensures character deletion and state ID prefix migrations cascade cleanly without manual cleanup.

## Exports

All exports are server-side. All sync DB calls require the caller to be inside a `Citizen.CreateThread`.

### Reads

```lua
-- Fetch a character by state ID.
exports['lw-characters-api']:GetCharacter(stateId)
-- returns: table|nil

-- Fetch the active character for a connected player via their lw-core session.
exports['lw-characters-api']:GetActiveCharacter(source)
-- returns: table|nil

-- Fetch all Active and Deceased characters for a player account.
-- Ordered by last_played_at DESC.
exports['lw-characters-api']:GetCharactersByLicense2(license2)
-- returns: table[]

-- Fetch slot usage and character list for a player account.
-- `used` counts Active characters only — Deceased do not consume a slot.
-- `characters` includes Active and Deceased rows.
exports['lw-characters-api']:GetSlotInfo(license2)
-- returns: { allowed: integer, used: integer, characters: table[] }

-- Check whether a first + last name combination is available for a player.
-- Checks lw_characters and lw_character_tombstones. Case-insensitive.
exports['lw-characters-api']:IsNameAvailable(license2, firstName, lastName)
-- returns: boolean

-- Fetch all Deceased characters with last known coordinates.
-- Used by lw-mortality on restart to rebuild corpse NPCs.
exports['lw-characters-api']:GetDeceasedCharacters()
-- returns: table[]

-- Fetch a tombstone by state ID.
exports['lw-characters-api']:GetTombstone(stateId)
-- returns: table|nil

-- Fetch all tombstones for a player account, ordered by died_at DESC.
exports['lw-characters-api']:GetTombstonesByLicense2(license2)
-- returns: table[]

-- Fetch all tombstones with a non-null epitaph, ordered by died_at DESC.
-- Used by memorial display resources.
exports['lw-characters-api']:GetMemorialEntries()
-- returns: table[]
```

### Writes

```lua
-- Create a new character row after a completed creation flow.
-- `data.stateId` must be pre-generated by lw-core:RequestStateId.
-- Validates name availability before insert.
exports['lw-characters-api']:CreateCharacter(license2, data)
-- data: { stateId, firstName, lastName }
-- returns: boolean, string|nil (success, error message)

-- Partially update a character row.
-- Whitelisted fields: first_name, last_name.
-- Status changes must go through SetCharacterStatus or SetCharacterDeceased.
exports['lw-characters-api']:UpdateCharacter(stateId, data)
-- returns: boolean

-- Write the character's last known position.
exports['lw-characters-api']:SaveLocation(stateId, coords, heading)
-- coords: vector3

-- Generic status setter. Use SetCharacterDeceased for permadeath.
exports['lw-characters-api']:SetCharacterStatus(stateId, status)
-- status: LWUtils.Enums.CharacterStatus value
-- returns: boolean

-- Atomically set status to deceased, record deceased_at, and write tombstone.
-- epitaph is optional. If nil, tombstone is written but no memorial entry created.
-- 250 char cap enforced — returns false with an error message if exceeded.
-- Called by lw-mortality during the permadeath choice flow.
exports['lw-characters-api']:SetCharacterDeceased(stateId, epitaph)
-- returns: boolean, string|nil (success, error message)

-- Hard delete a character row. CASCADE cleans all extension tables.
-- No tombstone is written. For forced pruning only.
-- lw-mortality uses SetCharacterDeceased followed by DeleteCharacter after 7 days.
exports['lw-characters-api']:DeleteCharacter(stateId)
-- returns: boolean
```

## Events

### Fired by this resource

| Event | Args | When |
|---|---|---|
| `lw-characters-api:characterCreated` | `license2, stateId` | Character row first written |
| `lw-characters-api:characterDeleted` | `stateId` | Hard delete executed |
| `lw-characters-api:characterStatusChanged` | `stateId, newStatus, oldStatus` | Status column updated |
| `lw-characters-api:pruningRequired` | `source, over` | Player is over their slot allowance on connect. `over` = number to delete |

## Character Status

Status values are defined in `LWUtils.Enums.CharacterStatus` (lw-shared):

| Value | Meaning |
|---|---|
| `active` | Normal playable character |
| `deceased` | Permadeath chosen. 7-day NPC ragdoll managed by lw-mortality. Row persists until lw-mortality calls `DeleteCharacter` |

Deceased characters do not count against a player's slot allowance.

---

## Permadeath Flow

1. Player downed → lw-mortality presents the permadeath choice
2. Player chooses permadeath → prompted for an epitaph (optional, 250 char max)
3. lw-mortality calls `SetCharacterDeceased(stateId, epitaph)`
4. Status set to `deceased`, `deceased_at` recorded, tombstone written atomically
5. After 7 days → lw-mortality calls `DeleteCharacter(stateId)`
6. Character row deleted, CASCADE cleans extension tables, tombstone persists permanently

No epitaph → tombstone still written (name is permanently locked on the account) but the character does not appear in memorial entries.

## Pruning Flow

1. Player connects → `lw-core:playerConnected` fires
2. This resource checks Active character count against slot allowance
3. If over allowance → `lw-characters-api:pruningRequired` fires
4. lw-character-selection loads but blocks interaction until resolved
5. Player deletes characters via `DeleteCharacter` until within allowance
6. No tombstone is written for pruned characters — names become reusable

## Epitaph Display

Epitaphs are stored as raw text. Word-wrap for display at render time:

```lua
local LWUtils = exports['lw-shared']:GetUtils()
local lines = LWUtils.Utils.String.WrapText(tombstone.epitaph, 50, 5)
```

50 characters per line, max 5 lines, never breaks mid-word.
